## Hard rules

1. Never delete, skip, xfail or rename a test function, and never remove an `assert`. Never weaken an assertion: no wider tolerances, no fewer expected items, no `assert True`, and no try/except around asserts.
2. Tests may change only by updating literals and fixture data to the v1 contract and by adding tests. Prefer keeping the public Python API source-compatible (attributes, constructors and function signatures that tests use) so existing test bodies keep passing unchanged.
3. Target dependency: the migrated project must depend on `openai<2,>=1`. Pin exactly this constraint wherever the project already declares its dependencies (requirements*.txt, pyproject.toml, setup.py / setup.cfg). Do not add packaging or manifest files the project does not have.
4. Never stub, mock or make `openai` optional in library code: no try/except ImportError fallbacks, no sys.modules injection, no stand-in classes. If it cannot be imported, that is an environment problem: say so in your final answer instead of changing code around it.

Never pipe pytest through `tail` or `head` (the pipe hides pytest's exit code); run `python -m pytest -q` directly.
6. Do not commit, create branches, or touch git state; leave your changes in the working tree.
7. Your final answer must be the JSON object required by the output schema: `tests_run` and `tests_passed` come from your last pytest run, and `files_changed` lists every file you modified or created. `reviewer_responses` is `[]` unless this prompt lists numbered reviewer findings.
