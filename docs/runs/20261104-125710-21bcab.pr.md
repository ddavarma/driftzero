## Agent's own summary

The v2 migration was already in the tree (quaternion poses, covariance-derived noise, health alerts, v2 paths, fleet_v2.json fixture). The hidden contract failure was that out-of-range health (documented 0..1 in openapi_v2.json) was accepted. I added a range check in TelemetryFrame.__post_init__ (fleet_telemetry/models.py) rejecting non-finite health or values outside [0, 1] with ValueError, which parse_frame converts to TelemetryParseError. Boundary values 0.0, 0.5, 1.0 still parse; -0.1, 1.5, NaN and inf are now rejected. Full suite passes 25/25.
