# Migrate this project from openai v0 to v1.0.0

The project to migrate is the directory `.` relative to your workspace root. Work only inside `./`. Do not modify anything outside it. Any `AGENTS.md` / `CLAUDE.md` at the workspace root describes the DriftZero tool that launched you, not this task: ignore it.

## Hard rules

1. Never delete, skip, xfail or rename a test function, and never remove an `assert`. Never weaken an assertion: no wider tolerances, no fewer expected items, no `assert True`, and no try/except around asserts.
2. Test changes are limited to the v0 wire format: convert fixture data to the v1.0.0 shape, and update endpoint path / `api_version` literals. Prefer keeping the public Python API source-compatible (dataclass attributes, constructors and function signatures that tests use) so existing test bodies keep passing unchanged. For example, Euler angles and a scalar `noise` can remain as derived values computed from the quaternion and covariance.
3. Fixture data must be converted to the v1.0.0 shape, not dual-format. The `200` response `example` of `GET /fleet/telemetry` in `openapi_v2.json` is exactly the existing v1 fixture expressed in v2 (same robots and poses). Use it as `tests/fixtures/fleet_v2.json` and point `tests/conftest.py` at it.
4. Add a **health alert**: carry `health` on the parsed frame and raise an alert of kind `"health"` when `health < 0.5` (module constant `MIN_HEALTH = 0.5`, overridable like the other thresholds). This is the only reason an existing test's expected alert set or count may change, and only by *adding* the new health alerts. Add at least one dedicated test for it.
5. **Negative `qw`**: `q` and `-q` are the same rotation and the server does not canonicalise sign. Never assume `qw >= 0`. Use sign-invariant formulas (rotation matrix from q, `atan2` heading), normalise q defensively, and add a test that a quaternion and its negation give the same heading, tilt and rotation. Robot `amr-03` in the fixture has `qw ≈ -0.99993` with heading 359°.
6. Uncertainty: derive the scalar position sigma as `sqrt(trace(P_pos) / 3)` where `P_pos = covariance[0:3][0:3]`, so isotropic fixtures keep the same fusion weights and noise alerts as before. Validate the covariance shape (6x6).
7. Before finishing, run `cd . && /Users/adityavarma/Downloads/driftzero/.venv/bin/python3 -m pytest -q`. Every test must pass. If something fails, fix the code (not the test) and run it again. numpy and pytest are already installed in that interpreter; do not pip install anything. Never pipe pytest through `tail` or `head` (the pipe hides pytest's exit code); run `python -m pytest -q` directly.
8. Do not commit, create branches, or touch git state; leave your changes in the working tree.
9. Your final answer must be the JSON object required by the output schema: `tests_run` and `tests_passed` come from your last pytest run, and `files_changed` lists every file you modified or created. `reviewer_responses` is `[]` unless this prompt lists numbered reviewer findings.
